# Редизайн chat — план по етапах

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** перенести в код готовий дизайн з канвасу «Chat redesign» (десктоп і телефон, світла й темна тема) на Mantine 9, вісьмома етапами. Етапи зливаються в гілку `develop`, а на prod редизайн іде одним злиттям `develop` → `main` наприкінці.

**Architecture:**
- **Дизайн.** Канвас «Chat redesign»: https://claude.ai/artifact/XLx5GvCkUuVC57mLRdFhid (приватний, 47 артбордів), копія в `docs/design/` (етап 0). Вигляд: шрифт Onest, один бірюзовий акцент (`brand-7` `#0B7A75` у світлій темі, `#3CC4B8` у темній), тло розмови з крапковим візерунком, бульбашки з радіусом 18px і кутом 4px як хвостиком.
- **Код.** Логіка, запити й мутації Convex не змінюються. Редизайн торкається:
  - теми Mantine (`src/theme.ts`: палітра, шрифти, радіуси, тіні, дефолти компонентів);
  - власних токенів через `cssVariablesResolver` зі значеннями для світлої й темної схем;
  - CSS modules і розмітки презентаційних компонентів.
  Кілька компонентів змінюють форму: налаштування стають панеллю, на телефоні з'являються нижні вкладки, нижня панель дій і нижні діалоги.

**Tech Stack:** Mantine 9.7 (`createTheme`, `cssVariablesResolver`, `localStorageColorSchemeManager`, `Drawer`, `Transition`), `mantine-contextmenu` 9.4, `@tabler/icons-react` 3, `@fontsource-variable/onest`, CSS modules + `postcss-preset-mantine` (`light-dark()`, міксини `light` / `dark`, `smaller-than`), Vitest + Testing Library, Playwright (e2e і MCP для звірки з канвасом).

**Spec:** канвас «Chat redesign», його копія `docs/design/*.dc.html` і розділ «Рішення» нижче.

## Як працювати з цим документом

Документ — єдине джерело стану редизайну між сесіями. Нова сесія читає розділ «Стан», потім розділ свого етапу, і більше нічого шукати не треба.

**Порядок одного етапу:**

1. `git switch develop && git pull`. Етап починається, лише коли попередній злитий у `develop` (стан ✅).
2. Гілка `redesign/<N>-<назва>` з таблиці «Стан», від `develop`. У таблиці ставиться 🟡.
3. Звірити розділ етапу з кодом: файли й імена могли змінитися після попередніх етапів. Якщо щось розходиться, спершу виправити цей документ.
4. Робота за кроками етапу: тест спершу, потім реалізація. Звірка з канвасом — знімки Playwright MCP на 1280px і 390px.
5. Перевірка перед здачею: `npm run lint && npm run typecheck && npm run test:once && npm run build && npm run test:e2e`. Етап, після якого e2e червоні, не здається: `develop` завжди має бути готовим до релізу.
6. Оновити цей документ у тій самій гілці:
   - галочки кроків;
   - у «Стані» поставити 🔵;
   - запис у «Журнал» — дата, що зроблено, відхилення від плану, що лишилось.
   Потім коміт.
7. 👤 Власник пушить гілку, відкриває PR **у `develop`** (не в `main`) і зливає. Номер PR і ✅ записує наступна сесія першим комітом свого етапу або окремим `docs:`-комітом.

**Гілки:**
- `develop` — інтеграційна гілка редизайну, створена від `main` 2026-11-09. Netlify її не збирає (deploy previews і branch deploys вимкнені, і так має лишитись: збірка запускає `npx convex deploy` і оновила б функції на prod). Перевірка — локально проти dev-деплойменту Convex.
- `main` — prod. Поки йде редизайн, у `main` потрапляють лише термінові виправлення prod: гілка від `main`, PR у `main`, потім `git switch develop && git merge main`, щоб `develop` їх не загубив.
- Реліз — етап 7: PR `develop` → `main`.

**Позначки:** ⬜ не почато · 🟡 у роботі · 🔵 чекає власника (пуш, PR, перевірка) · ✅ злито в `develop` (етап 7 — у `main`, тобто на prod).

## Рішення

Ухвалені власником, не переглядаються.

- **Етапи зливаються в `develop`, на prod — одним релізом** (2026-11-09, замінило рішення того ж дня випускати етапи окремо). Кожен етап — свій PR у `develop`. Prod не змінюється, поки етап 7 не зіллє `develop` у `main`, тож змішаного вигляду на prod немає.
- **Undo після видалення немає** (2026-11-09). Toast після видалення — «2 messages deleted» без кнопки. Діалог видалення лишається з текстом «This can't be undone». Відновлення видалених, якщо знадобиться, — окрема задача після редизайну.
- **Референси:** Telegram Web та iOS/Android, WhatsApp Web і mobile, Signal Desktop. Беремо їхні патерни (розкладка, поведінка, ієрархія), а не фірмовий вигляд: логотипи, фірмові кольори й іконки не копіюються.
- **Теми:** світла й темна. За замовчуванням — тема системи (`defaultColorScheme="auto"`). У налаштуваннях «Appearance»: `System` / `Light` / `Dark`. Вибір зберігається на пристрої (`localStorageColorSchemeManager`, ключ `chat-color-scheme`).
- **Розкладка десктопа** (від `md`):
  - бічна панель фіксованої ширини (на канвасі 360–420px), розмова на решту;
  - у шапці панелі — кнопка меню ☰ («Contacts», «Settings», «Night mode», «Log out») і пошук;
  - контакти й налаштування відкриваються в тій самій панелі зі стрілкою «назад», розмова праворуч лишається.
- **Розкладка телефона:**
  - список чатів на весь екран, знизу вкладки «Chats», «Contacts», «Settings»;
  - розмова відкривається поверх, виїжджаючи справа (200 мс, вимикається при `prefers-reduced-motion`);
  - висота — `100dvh`, щоб композер не ховався під клавіатурою.
- **Налаштування — панель, а не модалка:** `SettingsModal` замінюється на `SettingsPanel` у бічній панелі. Розділи:
  - **Profile** — великий аватар і ім'я;
  - **Notifications and sounds**;
  - **Appearance**;
  - **Account** — «Log out» і червоне «Delete account».
- **Стрічка повідомлень:**
  - фон розмови — тонкий візерунок на CSS/SVG без зовнішніх файлів, окремий для кожної теми;
  - хвостик лише в останньої бульбашки групи;
  - група — послідовні повідомлення одного автора з проміжком не більше 5 хв;
  - час і галочки всередині бульбашки внизу праворуч;
  - аватарів біля бульбашок у чатах 1:1 немає;
  - плашка дати липне до верху під час прокрутки (`position: sticky`);
  - кнопка «донизу» з лічильником непрочитаних.
- **Аватари без фото:** ініціали на кольоровому тлі. Колір детермінований від `userId`: 7 кольорів палітри з канвасу, функція `avatarColor(id)`. Для «Deleted account» — нейтральний сірий з іконкою.
- **Дії з повідомленням:**
  - на десктопі — контекстне меню `mantine-contextmenu` у стилі теми;
  - на телефоні довге натискання відкриває нижню панель (`Drawer position="bottom"`) зі списком дій і прев'ю повідомлення;
  - діалоги на телефоні — теж нижні панелі.
- **Композер:**
  - заокруглене поле, ліворуч у ньому кнопка емодзі;
  - пікер емодзі на десктопі — поповер 372px над композером: пошук і вибір відтінку шкіри зверху, «Recently used», категорія, прев'ю наведеного емодзі з назвою, вкладки категорій знизу;
  - на телефоні — панель 300px замість клавіатури з вкладками категорій зверху й комірками 44px;
  - повідомлення лише з 1–3 емодзі — 44px без бульбашки, час на плашці;
  - кнопка надсилання активна лише з непорожнім текстом;
  - панель відповіді чи редагування над полем з кольоровою лінією акценту.
- **Порожні стани:** «No chats yet» з кнопкою «Add contact»; «No contacts yet»; «Nothing found» (на канвасі — «No chats or contacts match “…”. To start a chat with someone new, add them by email.»); без відкритого чату — «Select a chat to start messaging».
- **Завантаження:** скелетони списку чатів і стрічки замість `LoadingOverlay`. Toast-и `@mantine/notifications` у стилі теми, нове повідомлення — з аватаром.
- **Розміри** (погоджено 2026-10-20, однакові на десктопі й телефоні):
  - **50px:** поля й кнопки на екранах входу та реєстрації, поле повідомлення, кнопки Send і New chat (50×50), пошук чатів і контактів, рядки мобільних налаштувань;
  - **44px:** решта кнопок і полів (діалоги, режим вибору, налаштування, пікер емодзі), рядки вибору звуку, рядки нижньої панелі дій на телефоні, перемикач теми (рамка 44, кнопки всередині 36), іконкові кнопки 44×44;
  - **40px:** пункти контекстних меню на десктопі (меню повідомлення й меню ⋮ чату);
  - **текст на кнопках:** 18px на кнопках 50, 16px на кнопках 44. Рядки мобільних налаштувань — 16px (це рядки списку, а не кнопки);
  - **аватари:** 50 у списку чатів — значок статусу 14×14, ім'я 16px, опис 14px; 44 у шапці розмови, контактах, Add contact і Forward to — значок 12×12, ім'я 15px, опис 13px. Значок статусу круглий, розмір разом із рамкою (`box-sizing: border-box`). Фото профілю в налаштуваннях — 104px на десктопі, 96px на телефоні;
  - **заголовки** «Sign in» і «Create account» — 30px; на телефоні Sign in без посилання «Forgot?» (скидання пароля немає).
- **Тексти UI** англійською, дослівно з канвасу. Якщо текст на канвасі розходиться з кодом чи константами `convex/chatRules.ts` / `authRules.ts`, перемагає канвас: константа й тести оновлюються в етапі, якому належить екран.

## Global Constraints

- Обмеження проєкту з `CLAUDE.md` лишаються в силі (версії, Mantine + CSS modules без Tailwind, ESLint-стиль, `ConvexError`, тест спершу, 👤-кроки, `Co-Authored-By`).
- **Кожен етап лишає `develop` готовим до релізу:** `npm run test:e2e` зелений у `desktop` і `phone`. E2E-селектори й тексти оновлюються в тому етапі, що змінив екран, а не наприкінці.
- **Темна тема — з етапу 1, без прапорця.** Етап 1 вмикає `defaultColorScheme="auto"`. Поки екран не перенесено, його старі CSS (`gray-*`, `white`) у темній темі виглядають зламаними — це очікувано в `develop` і зникає з етапом, що переносить екран. Кожен етап звіряє свої екрани в обох темах. Технічне рішення Claude (2026-11-09): на prod проміжних станів не буде, тож прапорець `VITE_DARK_MODE` з попередньої версії плану не потрібен.
- **Кольори лише через токени:** палітра Mantine (`--mantine-color-brand-*` тощо) і власні токени з `cssVariablesResolver`. Hex у CSS modules і JSX не пишеться, тільки в `src/theme.ts`, зі значеннями з артборду `Components`. Етап, що переносить компонент, прибирає з його CSS `gray-*`, `white` і `dark-*`.
- **Власні токени** (у CSS — `var(--chat-…)`, кожен зі значенням для `light` і `dark`):
  - тло: `--chat-sidebar-bg`, `--chat-bg`, `--chat-pattern`;
  - бульбашки: `--chat-bubble-in`, `--chat-bubble-in-text`, `--chat-bubble-out`, `--chat-bubble-out-text`, `--chat-bubble-meta`;
  - галочки: `--chat-tick`, `--chat-tick-read`;
  - бейджі: `--chat-badge`, `--chat-badge-muted`;
  - текст: `--chat-text`, `--chat-muted`, `--chat-accent-text`, `--chat-danger`;
  - решта: `--chat-online`, `--chat-line`, `--chat-hover`, `--chat-active`, `--chat-active-text`, `--chat-date-chip`, `--chat-date-chip-text`.
  Окремої таблиці токенів на канвасі немає. Значення для обох тем етап 1 виводить з палітри `colors` на `Components` (ролі background, chat background, field, border, line, text, muted, accent, outgoing bubble, chip, online, danger…), а те, чого в палітрі немає (вхідна бульбашка, час і галочки в бульбашці, кольори аватарів, toast), — з інлайн-стилів компонентів на `Components` і в `Chats.dc.html`. Відповідність «роль палітри → токен» записується коментарем у `src/theme.ts`. Токени, яких бракує в списку вище (наприклад, для toast-а), додаються під тим самим префіксом.
- **Контраст:** текст до тла щонайменше 4.5:1 (3:1 для тексту від 24px) в обох темах. Перевіряє тест етапу 1.
- Числа з канвасу округлюються до шкали Mantine (`xs`–`xl`, `rem(…)`). Розбіжність до 4px — норма.
- **Поля вводу** мають шрифт 16px на телефоні: iOS не збільшує сторінку при фокусі.
- **Розміри для дотику:** інтерактивні елементи щонайменше 44×44px.
- Шрифти — пакети `@fontsource-variable/*`, не Google Fonts з мережі.
- Перемикання десктоп/телефон — `md` (48em).
- Анімації коротші за 250 мс і поважають `prefers-reduced-motion` (`respectReducedMotion: true` у темі).
- Звірка з канвасом — знімки Playwright MCP на 1280px і 390px у світлій і темній темах проти `docs/design/<Ім'я>.dc.html`.

## Review Focus

1. **Темна тема і контраст.** Час і галочки в бульбашках, сірий бейдж замʼюченого чату, плейсхолдери читаються в обох темах. Тест контрасту токенів — етап 1; звірка знімками — етапи 2–6 для своїх екранів, повна — етап 7.
2. **Довге натискання на телефоні проти прокрутки й виділення.** Прокрутка стрічки не відкриває панель дій (`cancelOnMove`), системне виділення тексту не перебиває довге натискання (`user-select: none` на бульбашках лише на телефоні, копіювання — через «Copy»). E2E у проєкті `phone` — етап 6.
3. **Довге слово чи посилання без пробілів** не розпирає бульбашку й не дає горизонтальної прокрутки сторінки (`overflow-wrap: anywhere`). Тест і знімок — етап 5.
4. **Зміна теми системи при відкритому застосунку** в режимі `System` перемикає тему одразу, а ручний вибір переживає перезавантаження. Тест хука — етап 1; e2e і перевірка на prod — етап 7.
5. **Клавіатура на справжньому телефоні.** Композер лишається над клавіатурою, сторінка не масштабується при фокусі. Емуляція цього не покриває: 👤-перевірка на телефоні після етапу 5 і фінальна в етапі 7.
